# Building and running

```
./build.sh              # debug: build/tidalfast
./build.sh release      # optimized
./build.sh dist         # release package in build/dist
./build/tidalfast
```

On macOS it needs macOS 14 or later, Odin and the Xcode command line tools; [linux.md](linux.md) has what Linux needs, and [windows.md](windows.md) how to cross-build for Windows with `./build.sh windows`. `build.sh` compiles the shell to an object and has Odin link it into `build/tidalfast` with the app. Every build relinks the executable, so set `TIDALFAST_SIGN_IDENTITY` (see below), or the Keychain asks again for the saved login after each build (see [Keychain](tidal-data.md#keychain)). Shaders are compiled at runtime from source in `src/render`, so the Metal toolchain isn't needed.

`third_party` holds the C libraries the app links, each with its C source and Odin bindings: `kbts` with a copy of Odin's `vendor:kb_text_shape`, and `dr_flac` (dr_flac 0.13.3 from dr_libs) with bindings for the few procedures the player uses. The bindings link `build/kbts/kb_text_shape.a` and `build/dr_flac/dr_flac.a`. `build.sh` compiles each archive when it's missing, older than its source or built with other flags, so nothing is written to the Odin install, and on macOS it targets macOS 14 like the app. `./build.sh libs` builds only the archives. Run `./build.sh` once before `odin test tests`. Import these packages by relative path; `vendor:kb_text_shape` would link Odin's own archive. The project adds one function to `kb_text_shape.c`, `tidalfast_bidi_class`, which exports the library's Unicode bidi class table. Sound goes out through each OS's own API, declared by hand in `src/audio/bitperfect_<os>.odin`, so there is no audio library to build ([Playback](playback.md#output)).

`kb_text_shape.h` is patched in three places:

- Hangul. `kbts__HangulSyllableInfo` tested `Codepoint == 0xAC00` where it meant `>=`, so U+AC00 (가) was the only precomposed syllable it recognized. That one was split into jamo and never put back together: the syllable's jamo were treated as not composable, so 가 came out as two jamo glyphs twice as wide. Every other syllable was passed through untouched. On top of that, every glyph the Hangul pass made had codepoint index 0. Now all of U+AC00 to U+D7A3 is recognized, a syllable's own jamo always recompose, and the new glyphs keep the syllable's index and config. Apple SD Gothic Neo's Hangul now matches CoreText's glyph for glyph.
- Inserted glyphs. The dotted circle added before a stray mark and the nikhahit split off Thai and Lao sara am got index 0. They now take the index of the character they're inserted for.
- Font coverage. `kbts_FontCoverageTestCodepoint` asked the font for a glyph for every codepoint of a cluster, default ignorables included, so a font that doesn't map U+FE0F didn't cover 🏳️‍🌈 or 1️⃣ and the cluster went to the main font as missing glyphs. Noto Color Emoji is such a font. The shaper hides default ignorables anyway, so the test now skips them.

## Packaging

`./build.sh dist` builds an optimized app into `build/dist` and packs it. It writes nothing else in `build/`. `TIDALFAST_VERSION=1.2.3` sets the version. Without it the version comes from a `v1.2.3` tag on HEAD, or is 0.0.0.

On macOS it makes `TIDALfast.app` and `TIDALfast-<version>-macos-arm64.dmg`. The executable sits in `Contents/MacOS`. It is built for macOS 14, as `LSMinimumSystemVersion` in `packaging/macos/Info.plist` says. Odin and clang otherwise target the build machine's macOS, and the app wouldn't start on an older one. The static libraries they link target 14 too. Homebrew's Odin builds its vendor archives for the macOS it was installed on, which is why the project builds its C libraries itself (see above). The bundle is signed ad hoc, so Gatekeeper blocks a downloaded copy until the user allows it in System Settings > Privacy & Security or runs `xattr -dr com.apple.quarantine /Applications/TIDALfast.app`. Every release has a new ad hoc signature, so the Keychain asks again for access to the saved login after an update. `TIDALFAST_SIGN_IDENTITY` signs it with a real identity instead (see below).

### Signing identity

`TIDALFAST_SIGN_IDENTITY=name` makes `build.sh` sign the debug app and the dist bundle with that code signing identity instead of ad hoc. `name` is the certificate's name or SHA-1 as `security find-identity -v -p codesigning` lists them. An ad hoc signature's designated requirement is the hash of the code, so each relinked binary is a new app to the Keychain. With a certificate it is `identifier "com.tidalfast.app" and certificate leaf = H"..."`, the same for every build signed with it. After one "Always Allow", rebuilds stop asking for the saved login.

Any code signing identity works. A free one is a self-signed certificate: in Keychain Access, Certificate Assistant > Create a Certificate, with Certificate Type set to Code Signing. It only exists on the machine that made it, so it's for development; a bundle for other people still needs a Developer ID to get past Gatekeeper. The first build after setting or changing the identity relinks the shell, and that build asks for the login once more. `codesign` may also ask once for access to the certificate's private key. The `./build.sh measure` shell stays ad hoc.

On Linux it makes `TIDALfast-<version>-<arch>.AppImage` with [linuxdeploy](https://github.com/linuxdeploy/linuxdeploy) and its AppImage plugin, found on `PATH` or through `LINUXDEPLOY=path`. Run it with `APPIMAGE_EXTRACT_AND_RUN=1` where there's no FUSE, as in a container. The AppDir keeps `tidalfast` in `usr/bin`. linuxdeploy copies the libraries it links (libcurl and what it needs) into `usr/lib` and leaves out the ones every desktop has: glibc, Wayland, xkbcommon, fontconfig, FreeType and the Vulkan loader. The libcurl it carries is Debian's and looks for CA certificates only in `/etc/ssl/certs/ca-certificates.crt`. openSUSE has no file there, so `src/cacert` gives curl the system's own bundle when that file is missing. Build on the oldest distribution the AppImage should run on, since it needs that glibc or newer. Ubuntu 24.04 is the oldest Ubuntu with the fractional-scale protocol the shell uses.

`packaging/icon.svg` is the icon. `tools/icon.sh` renders it to `packaging/macos/AppIcon.icns` and `packaging/linux/tidalfast.png`, which are committed so the build needs no SVG renderer. It needs `rsvg-convert` (`brew install librsvg`) and `iconutil`.

`.github/workflows/release.yml` runs `./build.sh dist` on macOS 15 and Ubuntu 24.04 when a `v*` tag is pushed, and publishes the .dmg and the AppImage as that tag's GitHub release. A tag with a hyphen, such as `v0.2.0-beta.1`, makes a prerelease. A release made in GitHub's UI pushes its tag too, and the workflow adds the two files to that release instead of making another, so the title, notes and prerelease box are whatever the UI was given. Running the workflow by hand builds both and keeps them as workflow artifacts without releasing anything.

## Logging and environment variables

The app logs through `core:log` to stderr, at info level and up, with the level, time and source line. Errors say what failed and its HTTP status or OS code, never tokens, URLs with their query or what the server sent.

Environment variables:

- `TIDALFAST_FAKE=1` shows a fake library instead of logging in to TIDAL, for working on the UI without an account. Its rows play sine tones. `TIDALFAST_BENCH=1` and `=text` imply it. It uses no settings file unless `TIDALFAST_SETTINGS` names one, so it starts with the default settings, bit-perfect output off, and saves no change.
- `TIDALFAST_API=url` sends every request, the login and cover downloads to `url` instead of TIDAL, for running against `tests/mock_tidal`. The login then goes in the Keychain under `tidalfast-mock`, so it never replaces a real one. Only debug builds and the `./build.sh measure` build take it, and only for `http` or `https` on `127.0.0.1`, `[::1]` or `localhost`. Any other value, an empty one included, or any value in a release build, makes the app log a warning and show the fake data, so a script that lost its mock URL never reaches the real login or TIDAL. Whoever runs the server at `url` gets the tokens of the account that logs in, so a release build never sends them anywhere but TIDAL.
- `TIDALFAST_KEYCHAIN=name` keeps the mock login under `name` instead of `tidalfast-mock`. It only works together with `TIDALFAST_API`, and never with `tidalfast`. Set without a mock URL the app takes, it shows the fake data, as a bad `TIDALFAST_API` does. A build that reads an item another build wrote makes the Keychain ask for access, so test runs can give a build its own item.
- `TIDALFAST_OVERLAY=1` shows the frame-time overlay from the start.
- `TIDALFAST_VOLUME=0.2` sets the volume slider at start, over the saved one. It isn't saved unless the slider moves.
- `TIDALFAST_AUDIO_NULL=1` plays to the null device, a thread of the player's own: the audio callback runs in real time, but nothing reaches the speakers.
- `TIDALFAST_AUDIO_CAPTURE=path` writes every sample the audio callback hands the device, after ReplayGain and volume, to `path` as a 32-bit float WAV. In bit-perfect mode it's what the HAL IOProc hands CoreAudio, or the process callback hands PipeWire. The header's sizes are filled in when the app quits; `tests/audio_check` and `tests/bitperfect_check` also read a file whose header still says 0. The header has the rate of the first device open; after a rate change the frames carry on at the new rate in the same file.
- `TIDALFAST_SETTINGS=path` keeps the settings (volume, bit-perfect, scrollbars, the player bar) in `path` instead of `~/Library/Application Support/tidalfast/settings.json`. The fake data uses only this file, never the default one. A run that shows the fake data because it has no mock URL uses no settings file at all, so bit-perfect output stays off and no file changes.
- `TIDALFAST_CACHE=dir` keeps the list cache's files in `dir/<user id>` instead of `~/Library/Caches/tidalfast/<user id>` (see [The list cache](tidal-data.md#the-list-cache)). Against `TIDALFAST_API` the default is `~/Library/Caches/tidalfast-mock`, so a mock never writes into a real account's cache.
- `TIDALFAST_PKCE_REDIRECT=url`: with no saved login the app finishes the PKCE login (see [Login](tidal-data.md#login)) with this address at start, so a script can log in to `tests/mock_tidal` without a browser. Debug and `./build.sh measure` builds only. Set without a mock URL the app takes, in any build, it shows the fake data, as a bad `TIDALFAST_API` does.
- `TIDALFAST_AUDIO_WINDOW_KB=n` sets how much of each track is kept downloaded (8 MB by default). A small window sends seeks back to the network, for measuring them.
- `TIDALFAST_NOW_PLAYING_LOG=1` makes the shell print Now Playing as macOS holds it, read back from `MPNowPlayingInfoCenter`, after every update, and every remote command it gets.
- `TIDALFAST_REMOTE_TEST="8:play,12:seek=10,20:pause,24:next"` makes the shell send those remote commands that many seconds after launch, through the same path as the media keys. The commands are `play`, `pause`, `toggle`, `next`, `previous` and `seek=seconds`.
- `TIDALFAST_SPALL=path` writes a [spall](https://gravitymoth.com/spall/) trace of every frame to `path`.
- `TIDALFAST_LOG_EVENTS=1` prints every input event.
- `TIDALFAST_LOG_HTTP=1` logs at debug level: a line per TIDAL request with its method, URL without the query, status, size and time, plus the TIDAL library's other debug lines, such as token refreshes. For each stream it also logs the playback info's quality and format and an outline of the DASH manifest: element and attribute names, value shapes with digits as 9, and only the length of URLs and long values.
- `TIDALFAST_LOG_RENDER=1` prints the draw calls and instances whenever they change, which while scrolling is about every frame.
- `TIDALFAST_SHELL_TEST="2:key=cmd+f;3:mark=にほんご;4:commit=日本語;6:ax-dump"` runs steps against the shell's own entry points that many seconds after launch, for checking text input and accessibility without a person at the keyboard. Steps are separated by semicolons. `key=cmd+shift+z` sends a key down and up. `mark=text`, `commit=text` and `unmark` call the view's `setMarkedText`, `insertText` and `unmarkText` the way an input method does, and `ime` prints what the view answers to NSTextInputClient's questions. `ax-dump` prints the window's accessibility tree as AppKit hands it to an assistive app, and `ax-press=label` sends AXPress to the first element whose label or value starts with `label`. `mark-range=l,n,text` and `commit-range=l,n,text` give a replacement range in UTF-16 units, and `commit-marked=text` replaces whatever `markedRange` answers. `clean=hex` prints what the shell's `field_sanitize` makes of the bytes, in hex. Commands joined with `|` run together with no frame between them. `capture=path` copies the last `TIDALFAST_CAPTURE` frame to `path`, `hide` and `unhide` hide the app and show it again as Cmd-H and the Dock icon do, and `quit` quits. On Linux, `size=w,h` makes the window w by h points, since a compositor with no person at it never resizes one. `wheel=n` turns the wheel n notches, `finger=dy` sends one touchpad scroll frame and `lift` ends the gesture, all through the shell's pointer callbacks, and `scrolled` prints the total scroll the app was sent. The comment above `setup_shell_test` in `shell.m` lists them; on Linux and Windows, the comments above `test_step` in `shell/common.c` and `os_test_step` in `shell_wayland.c` and `shell_win32.c` do.
- `TIDALFAST_CAPTURE=path` writes each presented frame to `path` as a TGA. It's for checking output when you can't take screenshots. Each frame goes to a temp file that's renamed over `path`, so copying `path` while the app runs gives a whole frame. It also keeps the window's drawables full size while the window is hidden or covered (see [Redraw](redraw.md)), so frames of a covered window still show it.
- `TIDALFAST_BENCH=1` scrolls the library's track table by itself and logs the CPU time per frame in three phases (see [UI](ui.md#performance)). `TIDALFAST_BENCH=text` does the same for the text test list (see [Text](text.md#performance)), in debug and `./build.sh measure` builds only, since release builds leave out the test screens. `TIDALFAST_BENCH=covers` does it on live data while covers stream in (see [TIDAL data](tidal-data.md#performance)). All of them keep asking for frames even when the window is covered.
- `TIDALFAST_MEASURE=1` prints startup marks and memory samples to stderr as `measure: {...}` lines. `=startup` also quits once the first track rows and their covers are drawn, and `=memory` runs the memory scenario and quits. `tools/measure` sets it; see [Measuring RAM and startup](measuring.md).

The backtick key toggles the frame-time overlay. It's off unless `TIDALFAST_OVERLAY` or `TIDALFAST_BENCH` is set; the benches draw it so their numbers include it. It plots the CPU time of the last 120 frames against 120 Hz and 60 Hz lines. Under the plot are the last frame's total CPU time and the time spent building it (ui: everything before `end_frame`), on macOS the GPU's time on the newest frame it has finished (gpu, from the command buffer's `GPUStartTime` and `GPUEndTime`, read without waiting, so a frame or two behind), its draw calls (blue dot) and instances (green dot), the text cache's run count and atlas pages, the keyed boxes in use, and the process's memory footprint (ram) and Metal's allocations (gpu), see [Measuring RAM and startup](measuring.md). `TIDALFAST_LOG_RENDER=1` also logs draw calls and instances to stderr whenever they change.

The app opens on the library screen, or the login screen when there's no saved login. Cmd-F or Cmd-L opens the search page with its field focused (see [Search](search.md)). In debug and `./build.sh measure` builds, Cmd-1 goes back to the library, Cmd-2 shows the text test screen (specimen lines and a 10,000-row list) and Cmd-3 the renderer test screen. F1 or Cmd-Shift-D outlines every UI box and shows the key, ID and size of the box under the mouse.

To run with Metal's validation layer, set `MTL_DEBUG_LAYER=1 METAL_DEVICE_WRAPPER_TYPE=1`.
